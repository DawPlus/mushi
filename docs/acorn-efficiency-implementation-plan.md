# Acorn Kit 토큰 절약 개선 실행안

상태: **설계 준비 완료, acorn-kit 원본 미수정**. 이 문서는 Mushi에서 확인된 Acorn Kit 설치본에 대한 이식용 작업 명세다. 원본 저장소 접근이 가능해지면 먼저 최신 구현을 재확인하고 필요한 변경만 적용한다.

## 목적 및 범위

- **첫 번째:** 같은 세션/역할에서 변하지 않은 문서가 반복해서 컨텍스트에 적재되는 일을 줄인다.
- **두 번째:** 소스·의존성·검증 범위가 동일한 명령의 PASS 결과를 불필요하게 다시 확인하지 않도록 한다.
- 공통 원칙: **안전성·검증 품질을 떨어뜨려 얻은 절약은 인정하지 않는다**. 새 데몬, 데이터베이스, 토큰 추정기, 중복 캐시 계층, 의존성 추가는 기본적으로 금지한다.
- 적용 저장소: `acorn-kit` **원본**. 현재 연결된 `mushi`에는 설계 문서만 남긴다. 아래 경로는 Mushi 설치본 기준이며 원본에서 실제 파일 위치를 확인해야 한다.

## 작업 A · 문서 재독 회피 (우선순위 P1)

**후보 위치:** `AGENTS.md` 템플릿, `acorn/agents/worker.md`, `acorn/workflow/handoff.md`, 필요 시 Planner/Reporter 안내. Acorn 설치본의 `AGENTS.md`는 이미 변경/맥락 손실 시 재독 규칙이 있다. 중복 설명을 새로 늘리기보다 하나의 명확한 규율로 정리한다.

**변경 방침**

1. 현 역할의 필수 문서와 선택 문서를 분리한다. 시작 시 `AGENTS.md` + 선택 티켓 + **현재 Next의 역할 가이드**만 로드하고, 보조 문서는 실제 필요한 시점에 로드한다.
2. **동일 대화 세션 + 읽은 내용이 남아 있고 + 파일 변경 증거가 없음**을 만족하면 해당 문서를 재독하지 않는다. 다른 에이전트/새 세션 또는 맥락 손실에서는 정확성에 필요한 최소 범위를 다시 읽는다.
3. 문서 캐시 무효화 조건을 구체화한다: 해당 파일 편집/갱신, Next/역할 전환에 따른 다른 가이드 필요, 세션/워크스페이스 전환, 해당 내용이 컨텍스트에서 소실됨, 의존 규칙 변경. 상태를 확신할 수 없으면 다시 읽는다.
4. 자동화에 강제할 별도 에이전트 런타임 훅이 현재 있는지 원본에서 확인한다. 없다면 **프롬프트 규율을 넘어 보장할 수 있다고 주장하지 않는다**. 체크리스트·가벼운 관찰 로그 수준만 고려한다.
5. 동일 내용을 AGENTS/worker/reporter에 세 번 복사하지 않는다. 짧은 단일 출처와 해당 문서에 대한 링크/참조를 우선한다.

**완료 조건:** 이전 동작을 보존하면서 안내문 중복이 증가하지 않고, 선택 역할 가이드만 조회하는 정상 예제·역할 변경/맥락 손실 예제가 테스트 또는 문서 검증을 통과한다. **실제 읽기 횟수 감소는 계측 전까지 미증명.**

## 작업 B · 검증 PASS 재사용 (우선순위 P1)

**후보 위치:** `acorn/workflow/gates.md`, `acorn/agents/worker.md`, `acorn/agents/code-reviewer.md`, `acorn/agents/reporter.md`, `acorn/scripts/ticket.cjs`의 검증·전환 코드 및 연관 테스트. 현재 gates.md에는 **명령+종료코드+입력 동일성** 확인 규칙이 이미 존재한다. 기존 검증 로직을 우선 재사용한다.

**핵심 입력 증거(최소한)**

- 실행 명령/옵션·작업 디렉터리·종료 코드(성공 여부)·수행 시점.
- 대상 소스 및 테스트·설정·lockfile의 **동일성 증명**: 현재 상태를 반영하는 Git HEAD와 관련 작업 트리 상태, 또는 비교 가능한 파일 해시. 단순 HEAD만으로는 미커밋 변경을 탐지할 수 없다.
- 검증 대상 범위/게이트/해당 티켓의 현재 수락 기준. 테스트 명령·관련 파일·의존성·요구사항이 바뀌면 해당 검증을 무효화한다.
- **Git 없는 프로젝트에서는** 신뢰할 수 있는 관련 파일 해시가 확보되지 않으면 재사용 금지. 증거가 부족하면 재실행한다.

**전환 동작**

1. 검증 직후 아주 작은 receipt를 남기고, 후속 역할은 동일성이 입증되는 기존 PASS만 재사용한다.
2. 관련 변경이 있으면 영향을 받는 검사만 재실행한다. 확실하게 관련 범위를 판단할 수 없으면 넓은 검증을 유지한다.
3. 새로운 code-review/security/e2e/docs 게이트는 과거 verification PASS로 통과시킬 수 없다. 독립 보안/리뷰 의무는 그대로.
4. `ticket.cjs pass`는 실제 실행된 게이트 증거를 기록하는 도구이며 **단순 캐시 존재로 생략한 리뷰를 자동 PASS 처리하지 않는다**.
5. 임의의 영구 글로벌 캐시 대신 **기존 ticket 영수증 또는 가장 작은 프로젝트 로컬 상태**를 검토한다. 상호 충돌·동시 수정·실패/중단 시 캐시를 신뢰하지 않는다.

**테스트 시나리오**

| 시나리오 | 기대 결과 |
| --- | --- |
| 동일 명령·동일 입력·동일 승인 범위 | 검증 결과 재사용 가능 |
| 소스 파일 일부 수정(미커밋 포함) | 관련 PASS 재사용 거부 |
| 테스트 파일·설정·잠금파일 수정 | 관련 PASS 재사용 거부 |
| 명령·옵션·cwd 변경 | PASS 재사용 거부 |
| 게이트/수락 기준 변경 | 이전 PASS로 새 의무 충족 불가 |
| 영수증 없음/불완전함 | 재검증 필요 |
| 이전 결과가 FAIL 또는 미완료 | 재사용 불가 |
| Next가 security/e2e 등으로 이동 | 게이트 새 검토 필수, 다른 게이트 PASS 재사용 금지 |
| Git 없는 프로젝트에서 입력 해시 미확인 | 재검증 필요 |
| 반복 실패·중단·병렬 수정 | 일관성 확인 전 PASS 재사용 금지 |

**완료 조건:** 위 조건에서 불필요한 중복 실행만 제거하고, stale PASS가 한 번도 승인되지 않음. 기존 CLI/티켓/문서 정합성 테스트가 모두 통과하며 외부 의존성이 추가되지 않음.

## 작업 C · 계측 및 비교 (A/B 구현과 별개)

Acorn의 Mushi dogfood 기록에는 호스트 제공 토큰 사용량이 없다. 수정 전후 **실제 토큰 %를 주장하지 않는다**. 구현 후 재현 가능한 같은 작업에서:

- 실제 호스트 input/output/cache 토큰 (제공될 때만);
- 역할 가이드·개발 규칙 재독 횟수, 같은 검증 명령의 중복 실행 수;
- 코드 변경 이후 반드시 수행된 안전 검증 및 실패/수정 횟수;
- 소요 작업 단위와 검증 성공 여부를 기록한다.

동일한 시작 상태와 모델/effort·작업 지시·검증 기준을 사용한 비교가 불가능하면 관찰 수치만 보고하고 절감률은 **N/A**로 기록한다. 상세 실험 조건은 `docs/acorn-benchmark.md`를 참고한다.

## 원본 연결 후 순서

1. acorn-kit 실제 버전/브랜치, AGENTS 템플릿·ticket CLI·관련 테스트 위치를 **부분 탐색**으로 확인한다.
2. **작업 A**를 먼저 작은 변경으로 진행하고 문서 정합성·기존 스캐폴드 테스트를 수행한다.
3. **작업 B**는 stale PASS 거부 테스트를 먼저 추가(RED)한 후 최소 코드로 GREEN을 만든다. 기존 전환·리뷰·기록 호환성을 확인한다.
4. **작업 C**에서 전후 로그/호스트 usage가 실제 확보될 때에만 수치를 기록한다.
5. 수행 후 Mushi의 `AGENTS.md`와 설치된 Acorn 파일을 안전하게 업데이트하고, Mushi 검증 명령을 실행한다. **사용자의 요청 없이는 커밋/배포하지 않는다.**

## 변경하지 않은 것

이번에는 `acorn-kit` 코드/템플릿·Mushi 제품 소스·Acorn 상태·티켓 보드를 수정하지 않았다. 설계 자료를 `mushi/docs/`에 추가했을 뿐이며 **작업 A/B는 아직 구현하지 않았다**.
