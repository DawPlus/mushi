# Acorn 토큰 효율 감사: Mushi 1차

상태: **구조 및 운영 감사 완료 / 실제 토큰 절감률 미측정**. 이 보고서는 Mushi 프로젝트의 실제 아카이브·설정과 이번 대화에서 관찰된 실행 패턴에 기반하며, 모델의 과금 토큰 로그나 Acorn 미적용 대조군을 확보한 결과가 아니다.

## 검증한 사실

- 아카이브 티켓 **8개**, 본문 총 **395줄**. 선언된 게이트: `docs` 8, `code-review` 7, `security` 2.
- `AGENTS.md` 64줄, `worker.md` 27줄, `tickets.md` 49줄, `reporter.md` 29줄. **파일 크기/줄 수는 토큰 사용량이나 과금액이 아니다.**
- `acorn/config.json`의 관련 파일 기본 예산은 **2개**이고, `validationCommands`에는 **8개 명령**이 등록되어 있다.
- 아카이브에는 모두 `verification: passed`, `repairs_used: 0`이 남아 있다. 하지만 실제 시행착오(생성 라우트 전 빌드 검사, TS/ESLint 호환성, NestJS 모듈 방식, CORS preflight, Prisma 설치 정책)가 있었으므로 **0은 실제 재작업 0건의 증거가 아니다.**
- 코드 리뷰 통과 기록은 있으나, 상당수는 현재 구현 에이전트가 같은 문맥으로 자체 점검한 결과다. **독립 리뷰와 동등하게 해석할 수 없다.**
- Acorn 미적용 실행, 호스트 제공 토큰 카운터, 캐시 토큰·비용 기록이 없다. **절감률은 N/A**.

| --- | --- | --- | --- |

## 구체적인 개선 우선순위

1. **P0 · 측정 먼저:** 다음 실작업부터 모델 호스트의 input/output/cache token과 모델/effort를 작업 전후로 기록. 불가능하면 N/A를 유지. 텍스트 길이로 실제 사용량을 환산하지 않는다.
2. **P0 · 실패 영수증 정확성:** 최초 실패, 원인, 수정, 재검증 결과를 `Attempts`에 한 줄로 남긴다. `repairs_used`는 티켓 CLI `fail` 기록만 의미할 수 있으므로 전체 재작업 횟수와 구분한다.
3. **P1 · 변하지 않은 문서 재독 방지:** 세션 내 `AGENTS.md`, 현재 역할 가이드, `docs/development.md`는 최초 1회만 읽고 내용 변경/맥락 손실 때에만 재독. 새 대화에서는 필요한 안내만 읽는 것을 유지.
4. **P1 · 검증 영수증 재사용:** 명령, 종료코드, 코드/잠금파일/설정 버전과 영향을 받는 범위를 기록해 변경 없는 PASS는 재호출하지 않는다. 단, 최종 Done 필수 증거를 생략하지 않는다.
5. **P1 · 도구 호출 최소화:** 계획 단계에서 티켓 목적/범위를 확정한 후 일괄 생성하고, 동일 역할의 연속 읽기·경미한 문서 수정은 가능하면 묶는다. 에이전트가 바뀌거나 위험 게이트를 넘어갈 때는 독립 검토를 보존.
6. **P2 · Quick 적극 사용:** 문서 수정·독립된 작은 설정 변경에는 Managed 남용을 피하고, 보안/공통 API/다중 파일 계약 변경만 티켓을 사용.
7. **P2 · 리뷰 품질 표시:** 단독 에이전트 자체 검토와 별도 에이전트의 독립 리뷰를 명확히 구분한다. 필요하면 별도 리뷰는 비용을 지불하고 유지한다.

## 측정 실험과 종료 기준

`docs/acorn-benchmark.md`에 기록된 Acorn 유/무 비교 실험을 유지한다. 동일 스냅샷, 동일 모델·effort·테스트·수리 예산, 독립 워크스페이스, 최소 3회 교차 순서 실행, 실제 호스트 usage 및 테스트 결과 수집.

판정은 토큰뿐 아니라 품질과 재작업을 함께 비교한다. Acorn이 더 적은 토큰을 썼더라도 테스트/보안 품질이 떨어지면 절감으로 인정하지 않는다. 비교군이 없는 지금은 토큰 절약 결론을 보류한다.

## 이번 감사의 범위

읽은 자료: `AGENTS.md`, `acorn/config.json`, `acorn/workflow/tickets.md`, `acorn/agents/worker.md`, `docs/acorn-benchmark.md`, 일부 완료 아카이브. 확인 가능한 8개 티켓의 파일 수·줄 수·게이트 수를 로컬에서 집계했다. 전체 과거 툴 호출 로그나 결제 usage 데이터는 접근하지 못했으며, 불필요한 의존성/코드 변경 없이 문서만 추가했다.

**종합:** Acorn의 설계적 토큰 절약 잠재력은 있으나 이번 실사용에서 확인된 것은 워크플로 동작과 개선 지점이다. **실제 절감률은 확인되지 않았다.**
