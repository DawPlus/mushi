# T-261005-05 — Daily control-secret rotation + Serve handoff

## Goal
Automatically generate a fresh Onion **control token**, persist it, refresh Tailscale Serve, and produce a handoff payload (Serve URL + secret) that a notifier (Kakao) can send.

## Design (locked)
- **Secret format:** `word` + `digit(s)` + `word`, **max 10 characters** total (ASCII). Example shapes: `cat7dog`, `red12sky` only if length ≤ 10. Reject/regenerate if over length.
- **Word source:** small built-in short English word list (3–4 letters) so secrets stay pronounceable; no user dictionary required for v1.
- **Persist:** set `controlAuthMode=token` and `controlToken=<new>` in `~/.onion-bridge/web.json` (same path as Settings).
- **Serve:** after rotate, ensure web Serve points at current control port (reuse `onion serve` / `applyWebTailscaleServe` logic) and capture MagicDNS HTTPS URL from `tailscale serve status` when available.
- **Triggers:** CLI `onion rotate` for on-demand; daily via `launchd`/cron. v1 may also call `LifecyclePort.up()` so web+Serve are running before handoff.
- **LLM-ready shape (no LLM required in v1):** keep rotate/handoff behind small ports so a later LLM tool/router can swap in:
  - `SecretGeneratorPort` — default: word+digit+word; later: LLM-assisted phrases still ≤10 / policy-checked
  - `HandoffNotifierPort` — default: stdout; Kakao adapter in `T-261005-06`; later others
  - `IntentPort` — default: CLI flags / keyword skill; later SpaceXAI (`XAI_API_KEY`, `https://api.x.ai/v1`) for natural language
  - `LifecyclePort` — `T-261005-07` status/up/stop (chatbot can start web+Serve)

## Do

- Add rotate flow: generate → save web settings → ensure lifecycle up (or call Serve refresh) → return `{ url, secret, controlPort, rotatedAt }`.
