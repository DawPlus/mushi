# T-261005-01 — Add OAuth protection to MCP endpoint

## Goal
Replace Onion Bridge's single static bearer-token check with an OAuth-ready MCP authentication layer so external clients can authenticate safely without sharing one long-lived local token.

## Do
- Add auth mode configuration with at least `none` and `oauth`; keep the current simple mode available for local/dev compatibility during migration.
- In `oauth` mode, protect `/mcp` with Bearer access-token validation instead of comparing against one configured token.
- Validate token signature and claims locally using the configured issuer/JWKS:
  - signature
  - expiry / not-before
  - issuer
  - audience
- Add scope checks for the initial Onion permission model:
  - `workspace:read`
  - `workspace:write`
  - `workspace:exec`
- Map existing tools to the minimum required scope; read-only tools must not require write/exec scope.
- Return standards-friendly `401` / `403` responses with `WWW-Authenticate` information so an OAuth-capable MCP client can discover why access was rejected.
- Expose OAuth protected-resource metadata/discovery information needed by the MCP client, driven by configuration rather than hard-coded provider URLs.
- Add config fields for OAuth issuer / authorization-server metadata, audience, JWKS source when needed, and supported scopes.
- Stop writing the legacy static Authorization header into the tunnel profile when OAuth mode is active.
- Replace the startup warning that says OAuth is unused with auth-mode-aware status/warnings.
- Add focused tests for valid token, expired/invalid token, wrong issuer/audience, missing scope, and legacy/local compatibility behavior.

## Keep
- Do not build a custom OAuth login/password system in Onion Bridge in this ticket; Onion Bridge acts as the protected resource and validates tokens issued by a configured OAuth/OIDC authorization server.
- Do not allow OAuth claims/scopes to grant arbitrary shell or Git execution beyond Onion Bridge's existing tool allowlist.
- Keep localhost binding for the local MCP server.
- Never log access tokens, refresh tokens, client secrets, or full authorization headers.
- Preserve existing MCP request/response behavior after authentication succeeds.

## Done
- `/mcp` rejects unauthenticated OAuth-mode requests with a useful OAuth challenge.
- A valid access token from the configured issuer can call permitted MCP tools.
- Invalid/expired/wrong-audience tokens are rejected.
- Insufficient scope returns a controlled authorization failure.
- Read/write/exec tool permissions are separated by scope.
- OAuth mode no longer depends on the current shared static bearer token in the tunnel profile.
- Existing non-OAuth/local compatibility mode still starts and works as intentionally configured.
- Relevant tests pass and the package starts successfully.
