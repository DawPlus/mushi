# T-261005-04 — Remote access via Tailscale Serve (home-away)

## Goal
Make it safe and documented to use Onion Bridge from outside the home on the owner’s devices by putting **Tailscale Serve** in front of localhost web + MCP, without opening the LAN/internet raw ports.

## Design (locked for this ticket)
- **Path:** Tailscale Serve → `127.0.0.1` control port and MCP port. Onion keeps localhost bind.
- **Why:** For “my phone/laptop off-home”, Tailscale (WireGuard + tailnet ACL) is more stable and less publicly exposed than a generic public HTTPS URL. Cloudflare Tunnel is optional documentation only, not the primary implementation path.
- **Auth:** Remote use requires MCP auth (`token`/`oauth` from `T-261005-01`) and control auth from `T-261005-03`. Do not document a remote setup that leaves `none`/open control API as the happy path.
- **Clients:** Browser → Serve URL for dashboard; MCP client → Serve URL for `/mcp` with bearer/OAuth token.

## Do
- Add a short project-owned runbook (under `docs/`, not `acorn/`) covering: install Tailscale on home machine + client device, `tailscale serve` (or equivalent) for web `:3847` and MCP profile port, auth env/settings checklist, verify from a second device off LAN.
- Optionally add a tiny helper (CLI subcommand or script) that prints recommended `tailscale serve` commands from current settings/ports—only if it stays thin; otherwise runbook-only is enough.
- Document failure modes: home PC asleep, Serve not running, wrong port, missing auth headers, MagicsDNS/`*.ts.net` vs raw Tailscale IP.
- Add a brief “Cloudflare Tunnel alternative” appendix (high level only)—no requirement to implement CF automation.
- Call out ChatGPT/OpenAI Secure MCP Tunnel as a **separate** path (unchanged); Tailscale remote access does not replace it.

## Keep
- Do not change default listen address away from localhost as part of remote access.
- Do not require Cloudflare for the primary path.
- Do not implement Funnel/public-internet exposure as default; prefer tailnet-only Serve. If Funnel is mentioned, mark it as higher risk and auth-mandatory.
- Do not put secrets into the runbook; reference env/settings names only.

## Done
- A new user can follow the runbook to reach web UI and MCP from a second device on the tailnet with auth enabled.
- Primary path is Tailscale Serve → localhost; CF is docs-only appendix.
- Remote happy path never recommends unauthenticated control/MCP.
