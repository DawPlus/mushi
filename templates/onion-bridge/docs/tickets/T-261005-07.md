# T-261005-07 — Web + Tailscale Serve lifecycle (status / up / stop)

## Goal
Make it obvious whether Onion **web** and **Tailscale Serve** are running, and provide start/stop from CLI (and later chatbot) without hunting terminal jobs.

## Do
- Persist a PID (and port) file under `~/.onion-bridge/` when `onion web` starts; clear on clean stop.
- `onion status` (and `pnpm status`): show web up/down (PID + `/api/health`), control auth mode, Tailscale Serve URL/handlers if any.
- `onion stop` (and `pnpm stop`): stop web via PID/SIGTERM (and child bridges best-effort), run `tailscale serve reset` or equivalent to disable Serve proxy.
- `onion up` (and `pnpm up`): start web in background if down, then apply web Tailscale Serve (reuse serve helper); print URL + whether control auth is ready.
- Keep chatbot/LLM-facing surface as a small **LifecyclePort** (status/up/stop) so a later skill/LLM tool can call the same functions.

## Keep
- Do not bind away from localhost.
- Do not force Funnel.
- Do not stop unrelated user Tailscale features beyond Serve config reset for this node’s serve handlers.

## Done
- From a fresh shell, `pnpm status` shows clear on/off; `pnpm up` brings web+Serve; `pnpm stop` tears them down.
- Focused tests for PID helpers / status parsing with mocks where needed.
