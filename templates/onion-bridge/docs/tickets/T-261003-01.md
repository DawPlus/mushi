# T-261003-01 — Web Onion control MVP

## Goal
Build one end-to-end web control MVP that lets a user manage multiple project folders, turn Onion on/off per project, see exactly which projects are currently active, and edit required Onion setup values from Settings.

## Do
- Add minimal local-only backend API beside the existing Onion Bridge server/CLI.
- Support adding/selecting workspace folders from the web UI with a Finder-style folder picker flow where the platform permits it; provide a clear manual absolute-path fallback when browser security prevents native folder browsing.
- Display projects as a polished list/grid with project name, path, profile/tunnel, active state, and start/stop controls per project.
- Start/stop Onion per project folder and report which project(s) are currently active.
- Report each active project's workspace, profile/tunnel name when known, process state, and recent errors/log hints.
- Build TanStack UI in `apps/web` with dashboard/project list, per-project controls, active-status visibility, and settings page.
- Add Settings controls for required Onion setup values including tunnel ID, API key, tunnel-client path, default profile, control port, and configured project folders.
- Preserve and show existing saved values where safe; never render full secrets.
- Wire the UI directly to the backend API created in this ticket.

## Keep
- Bind control API to localhost only.
- Do not expose OpenAI API keys or bearer tokens in API responses; masked display only for secrets.
- Do not change existing `onion` CLI behavior unless required for shared code reuse.
- Keep UI inside `apps/web`.
- Use existing Tailwind setup; do not add styling dependencies without a clear need.
- Design quality matters: clean hierarchy, pleasant project cards/list, obvious controls, responsive layout, polished settings form.

## Done
- User can add/select existing project folders from the web UI.
- Each project row/card has clear on/off controls.
- Multiple configured projects can show independent active/inactive status, or any intentional single-active limit is removed from UI/API and tests.
- Status clearly shows which project folder(s) currently have Onion running.
- Dashboard shows idle, starting/running, stopping, and error states.
- Settings page can view/update required Onion setup values while masking secrets.
- Existing saved setup/profile values are shown or represented safely instead of being hidden.
- `apps/web` builds successfully.
- Focused verification command(s) documented in completion report.
